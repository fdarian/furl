# Fetch strategies

These three cheap, keyless probes are furl's default `order`. In the plugin `order` grammar they're named `default:raw`, `default:direct`, and `default:md-suffix` — the first three entries of furl's canonical `default:*` expansion. If all three decline, furl fails rather than trying a provider automatically; add `default:jina` (or `default:*` for all six built-ins) to `order`, or pass `--plugin jina`, to fall through to the provider builtins ([jina](/plugins/builtins/jina), [exa](/plugins/builtins/exa), [firecrawl](/plugins/builtins/firecrawl)).

## `default:raw`

If the URL pathname ends with a file extension (`.md`, `.txt`, `.json`, etc.), furl fetches the body as-is. Reports `↳ via raw` — the `default:` prefix is only how `order` names this built-in, not the printed source label.

## `default:direct`

For non-file URLs, furl sends a `GET` with `Accept: text/markdown`. If the response `content-type` contains `markdown`, it returns the body. Reports `↳ via direct`.

## `default:md-suffix`

If the direct fetch doesn't return markdown, furl retries the same URL with `.md` appended before any query string. A successful markdown response reports `↳ via md-suffix`.

## Why probes run first

These three strategies cost one extra HTTP request and no money. The provider builtins (`default:jina`, `default:exa`, `default:firecrawl`) cost a metered API call, or a rate-limited proxy hop for keyless jina — that's why they're opt-in rather than part of the default `order`. Even once enabled, furl's canonical `default:*` order always tries the free probes first, so a paid or rate-limited provider never runs ahead of a probe that might have succeeded anyway — see [Overview](/plugins/overview) for the full `order` grammar.
