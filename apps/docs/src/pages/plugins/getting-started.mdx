## Installing

```sh
furl plugins install https://github.com/someone/furl-x
```

furl clones the repository into a temporary folder, shows where it came from (and the `name` and `description` from its `package.json`, if it has one), and asks for confirmation before running any of the plugin's code. It then moves the plugin to `~/.config/furl/plugins/<name>`, where `<name>` is the plugin's manifest `name`, and puts `plugin:<name>` first in `order`. Pass `--yes` to skip the prompt (required in non-interactive sessions). Only `https` and `ssh` URLs are accepted. Installing fails if a plugin with that name is already installed.

## Uninstalling

```sh
furl plugins uninstall x
```

This removes `plugin:x` from `order`, the `plugins.x` entry and its stored secrets, then deletes the folder. It works even if the folder is missing or the plugin is broken, because nothing is imported.

## Configuring

### Managing interactively

```sh
furl plugins        # interactive: pick an installed plugin and configure it
furl plugins list   # list installed plugin folders and whether each is in `order`
```

The interactive flow lists the installed plugins that are in `order` and renders a config form from the selected plugin's manifest. furl only runs plugin code for plugins listed in `order`; `furl plugins list` reads folder names without importing anything.

### How it's written in the config

```jsonc ~/.config/furl/config.json
{
  "order": ["plugin:plugin-a", "plugin:some-other-plugin", "default:*"],
  "plugins": {
    "plugin-a": { "apiKey": "secret:x-api-key", "mode": "metadata" }
  }
}
```

- `order` controls the resolver precedence chain — see [Fetch strategy](/fetch-strategy). A plugin only runs if it's listed there as `plugin:<name>`.
- `plugins[<id>]` is the config object handed to that plugin. To disable a plugin, remove it from `order`.
- A plugin can reference a [secret](#secrets) rather than keeping a sensitive value like an API key in plain text.

## Secrets

Secrets are stored in the operating system's native secret manager.

Use `furl secrets set <name>` to create a new secret:
```sh
furl secrets set x-api-key
```

Then reference it from the config as `"secret:x-api-key"`.

These secrets are kept apart from the API keys saved by `furl providers`, so a name like `exa` can't read or overwrite a provider key. The name and value can't be empty.

### Further reading

<Expandable title="Plugins can register secrets for you">

A `secret`-typed manifest field configured via `furl plugins` does both writes for you — the value goes to the keychain, and a `{ <key>: "secret:<name>" }` reference goes into `config.json` — so plugin authors and users don't need to run `furl secrets set` and hand-edit config separately.
