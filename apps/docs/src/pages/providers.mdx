# Providers

`furl` supports three providers for the final conversion step.

## jina

- Default provider
- Keyless by default
- Uses `https://r.jina.ai/<url>`
- Requests markdown with `X-Return-Format: markdown`

If you set `JINA_API_KEY` or store a `jina` key with `furl providers`, `furl` attaches it to raise rate limits. Missing Jina credentials never block fetching.

## exa

- Requires `EXA_API_KEY` or a stored `exa` key
- Sends `POST https://api.exa.ai/contents`
- Uses `x-api-key`
- Returns clean extracted text at `results[0].text`

Exa does not return structured markdown in this implementation. It returns clean text.

## firecrawl

- Requires `FIRECRAWL_API_KEY` or a stored `firecrawl` key
- Sends `POST https://api.firecrawl.dev/v1/scrape`
- Uses `Authorization: Bearer <key>`
- Requests `formats: ['markdown']`

Firecrawl returns structured markdown at `data.markdown`.

## Key resolution

Provider keys resolve in this order:

1. Environment variable override
2. OS keychain entry saved by `furl providers`

If `exa` or `firecrawl` has no configured key, the CLI fails with a typed `NoProviderKey` error and tells you to run `furl providers`.

## `furl providers` (deprecated)

`furl providers` is kept working as a deprecated alias for managing the jina/exa/firecrawl keychain entries:

- Saving an `exa` or `firecrawl` key also makes that provider the default
- `Set as default` puts that provider's `default:<name>` token into the `order` config ahead of the other providers — but still behind the free `raw`/`direct`/`md-suffix` probes, which always run first regardless of which provider is default. Setting a default provider picks which provider wins if the probes decline; it never makes furl skip straight to a paid or rate-limited call for a URL the probes could have handled for free.
- Deleting the key for the current default removes its token and puts `default:jina` there instead

jina/exa/firecrawl are `default:` built-in resolvers (see [jina](/plugins/builtins/jina), [exa](/plugins/builtins/exa), [firecrawl](/plugins/builtins/firecrawl)), and they're opt-in: furl's default `order` only runs `raw` → `direct` → `md-suffix` until something adds a provider's token. `furl providers` is one way to do that; you can also edit `order` by hand — add `default:jina` (or `default:*` for furl's full canonical order — `raw`, `direct`, `md-suffix`, `jina`, `exa`, `firecrawl`) — or pass `--plugin jina` for one call. See [Overview](/plugins/overview).

If `config.json` has an older, standalone `provider` field, furl still honors it — folded into `order` for that run — but prints a deprecation notice on every use. Run `furl providers` once (e.g. "Set as default") to persist the equivalent `order` entry and drop the field for good.

- `-p/--provider` (deprecated) forces that single resolver directly for one invocation, the same as `--plugin <name>` (e.g. `--plugin jina`) — it skips the `raw`/`direct`/`md-suffix` probes entirely, not just the final fallback step. Prefer `--plugin` or the config `order` key.

jina/exa/firecrawl keys are not yet exposed as `furl plugins` config fields — they still live under `furl providers`, using the same keychain (`com.fdarian.furl`) as plugin `secret:<name>` references. See [Getting Started](/plugins/getting-started) for the plugin config/secrets flow.
