## Behavior

furl comes with a predefined chain of resolvers that probes what a website supports.

The default chain has three resolvers. They're tried in order, and the first one that succeeds wins.

<Steps>

<Step title="default:raw">

> Fetch `../file.ext` as-is

If the URL pathname ends with a file extension (`.md`, `.txt`, `.json`, etc.), furl fetches the file as-is, just like a regular curl.

<Expandable title="HTML responses are skipped">

It matches on any file extension, not on file type. If the server answers with `text/html` (for example `/wiki/Node.js`), `raw` steps aside and the next resolver runs instead of returning markup.

</Expandable>

</Step>

<Step title="default:direct">

> Try the `Accept: text/markdown` header

For non-file URLs, furl sends a `GET` with `Accept: text/markdown`. If the response `content-type` contains `markdown`, it returns the body.

</Step>

<Step title="default:md-suffix">

> Try appending `.md`

If the direct fetch doesn't return markdown, furl retries the same URL with `.md` appended before any query string.

</Step>

</Steps>

### Further reading

<Expandable title="Knowing what was used">

furl logs the order token of the resolver that produced the result (`↳ via default:md-suffix`, `↳ via plugin:x`) at the end of the output:
```
❯ furl some-url.com
## Content
Some content in markdown

↳ via default:md-suffix
```

That line goes to stderr, so it never ends up in a file or a pipe:
```bash
❯ furl https://vercel.com/design.md > design.md
↳ via default:raw

❯ cat design.md
[clean output]
```

</Expandable>

<Expandable title="Configuring the order">

Every resolver can be customized: reorder them, remove them, or add your own through [plugins](/plugins/overview).

Here's the default:
```json ~/.config/furl/config.json
{
  "order": ["default:*"]
}
```

`default:*` expands to the three probes above, in that order. Or you can specify them individually (e.g. `default:raw` and `default:md-suffix`)

</Expandable>

## Additional resolvers

You can fall back to a third-party provider to handle the `url → markdown` parsing.

- [jina](/plugins/builtins/jina)
- [exa](/plugins/builtins/exa)
- [firecrawl](/plugins/builtins/firecrawl)

Configure it with:

```jsonc ~/.config/furl/config.json
{
  "order": [
    "default:*",
    // ... ↓ when everything above declines ...
    "default:exa"
    // or "default:jina", "default:firecrawl"
  ]
}
```
