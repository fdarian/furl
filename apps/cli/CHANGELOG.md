# furl-cli

## 0.3.0

### Minor Changes

- 58ae7e8: Deleting an Exa or Firecrawl key in `furl providers` now removes its `default:<provider>` token from `order` instead of switching to jina. `furl providers` migrates a legacy `provider` field to `order` right away, and saving a jina key prints a hint when `default:jina` isn't in `order`. Config writes keep unknown fields, and `--resolvers` runs no longer read or warn about the config file.
- 5357366: Plugin config values written as `"secret:<name>"` are resolved from the OS keychain before the plugin runs. Add `furl secrets set <name>` to store a secret, and let `furl plugins` prompt for a plugin's declared config fields, saving `secret` fields to the keychain as `<plugin>.<field>`. `furl plugins uninstall` now also deletes the plugin's keychain secrets.
- 0748502: `furl plugins` no longer crashes when prompting for a string, number or secret field, and the form is more careful: a required secret with nothing stored is asked again, secrets are written to the keychain only after every field is answered, optional booleans and numbers can be skipped, and a saved enum choice is preselected. Secrets set with `furl secrets set <name>` (and `secret:<name>` references) now live in their own keychain namespace, separate from the `exa`, `firecrawl` and `jina` provider keys, so previously stored generic secrets must be set again; empty names and values are rejected. Plugin manifests are validated: the name must match `^[a-z0-9][a-z0-9_-]*$` and `config` fields need a safe `key`, a known `type`, and non-empty `options` for enums. `furl plugins uninstall` now deletes every `secret:<plugin>.*` reference in the plugin's saved config.
- 402f626: Plugins are now identified by their folder: `~/.config/furl/plugins/<name>` where `<name>` is the manifest name, and furl only imports the plugins listed in `order` (`plugin:<name>`). A plugin that fails to load now fails the fetch instead of being skipped with a warning, and a folder whose manifest name differs from its folder name is rejected. `furl plugins list` and `furl plugins uninstall <name>` no longer import any plugin code, so a broken or missing plugin can still be listed and uninstalled; uninstall removes stored secrets first, then updates the config and removes the folder, so a keychain failure can be retried. `furl plugins install` clones into a temporary folder, shows the URL and `package.json` name/description, asks for confirmation before importing any plugin code, refuses to overwrite an installed plugin, and rolls back if registering it fails. Git clones use `--` before the URL, only `https` and `ssh` URLs are accepted (`git:` is dropped), hosts starting with `-` are rejected, credentials are redacted from stored errors and stripped from the cloned remote. `furl plugins` (configure) only offers plugins listed in `order`.
- c5537a7: Add `furl plugins install`, `furl plugins list`, and `furl plugins uninstall` for managing local plugins.
- 778acab: API providers are now opt-in: a config without an `order` uses only `default:*` (raw, direct, and `.md`-suffix probes), so API keys alone never trigger a third-party request. Selecting a provider with `furl providers` writes its `default:<name>` token into `order`. Configs with the legacy `provider` field are migrated to that order on read/write, with `order` taking precedence when both fields exist. The removed `--provider` flag is replaced by `--resolvers 'default:*,default:<name>'` for a per-call provider override.
- d2913bf: Resolver failures are now recorded and reported instead of hidden or aborting the chain: `raw`, `direct` and `md-suffix` transport errors surface in the "no resolver could produce markdown" summary, `raw` skips `text/html` responses, and a plugin returning anything other than `{ markdown }` or `null` is reported as a failure. `↳ via` and failure lists now show the order token (`default:jina`, `plugin:x`). An empty `order` or `--resolvers` is rejected, order tokens are validated before plugins are loaded, and a missing or unreadable `secret:` reference fails the fetch instead of falling through to the next resolver. Error messages for fetch, provider, keychain and plugin-load failures are no longer empty.
